# Умные экраны в ЖК — B2B-сайт с калькулятором размещения

Заменяет пересылку Google-таблицы клиенту: рекламодатель сам выбирает города и жилые
комплексы — списком или на карте, — видит охват, количество контактов и стоимость,
сохраняет расчёт по ссылке. У отдела продаж есть отдельный режим со скидочной сеткой.

Оформление сделано в фирменном стиле Уфанета: пурпур `#951B81`, жёлтая кнопка действия
`#FFCA0E`, оранжевые акцентные блоки `#EF7D00`, шрифт Roboto, скругления 12 / 24.

Есть тёмная тема — переключатель в шапке. По умолчанию берётся системная настройка,
явный выбор запоминается в `localStorage`. В тёмной теме пурпур осветляется до `#D072C0`
(фирменный на тёмном фоне не проходит по контрасту), жёлтая кнопка остаётся фирменной,
а светлые тайлы карты инвертируются CSS-фильтром — маркеры при этом сохраняют свои цвета.

Стек: Next.js 15 (App Router) + TypeScript, карта на Leaflet и тайлах OpenStreetMap.
Данные — статический JSON, собранный из выгрузок исходной таблицы.

## Запуск

```bash
npm install
npm run build:data   # собрать src/data/dataset.json и public/dataset.json из data/source
npm run dev          # http://localhost:3000
```

## Две сборки из одного кода

| Команда | Что получается | Где нужен сервер |
|---|---|---|
| `npm run build` → `npm start` | полное приложение: сохранение расчётов через API, режим менеджера на cookie, скидочная сетка **не покидает сервер** | да, Node |
| `npm run build:static` | статический экспорт в `out/` для GitHub Pages: расчёт кодируется в саму ссылку, страницы менеджера и скидочной сетки в сборке нет | нет |

Серверные файлы называются `page.node.tsx` и `route.node.ts` — в статическую сборку они
не попадают, потому что `pageExtensions` в `next.config.mjs` их не подключает.

Для проектного сайта GitHub Pages нужен префикс пути:

```bash
BASE_PATH=/имя-репозитория npm run build:static
```

Деплой настроен в `.github/workflows/pages.yml`: при пуше в `main` GitHub сам собирает
статику и публикует её на Pages, подставляя `BASE_PATH` автоматически.

### Что теряется в статической сборке

* **Режим менеджера недоступен** — и это сделано намеренно. Без сервера скидочную сетку
  пришлось бы отдавать в браузер, где её увидел бы любой клиент. Для отдела продаж нужно
  поднять серверную сборку (`npm run build && npm start` на любом Node-хостинге или Vercel).
* Ссылка на расчёт длиннее: вместо короткого `/q/f7f298c712` получается
  `/quote/?d=…` — весь медиаплан сжат gzip-ом и уложен в адрес. Работает без бэкенда,
  ничего не хранится на сервере.

## Переменные окружения

Скопируйте `.env.example` в `.env.local`:

| Переменная | Зачем |
|---|---|
| `MANAGER_PASSWORD` | пароль входа в режим менеджера (`/manager`) |
| `SESSION_SECRET` | секрет для подписи cookie сессии; любая длинная случайная строка |
| `QUOTES_DIR` | где хранить сохранённые расчёты, по умолчанию `.data/quotes` |

## Страницы

| Адрес | Что это | В статике |
|---|---|---|
| `/` | лендинг: что за сеть, форматы, цены, география | да |
| `/calculator` | калькулятор: формат → срок → тематика → города → ЖК → смета | да |
| `/map` | карта всех ЖК: точка = комплекс, размер = число экранов | да |
| `/coverage` | полный список городов и ЖК с домами, экранами и охватом | да |
| `/requirements` | технические требования к макетам | да |
| `/rules` | стоп-лист по ФЗ-38 и правила для застройщиков | да |
| `/quote?d=…` | расчёт, зашитый в ссылку | да |
| `/q/<id>` | расчёт, сохранённый на сервере | нет |
| `/manager` | вход для отдела продаж | нет |

## Карта

Leaflet + тайлы OpenStreetMap, без ключей и регистрации. Точка — жилой комплекс
(координаты усреднены по домам), радиус зависит от числа экранов, цвет — от статуса:
пурпур в медиаплане, оранжевый доступен, серый закрыт для тематики застройщиков.
В попапе — охват, контакты, стоимость и кнопка добавления в медиаплан.

Выбор на карте и в калькуляторе — один и тот же черновик в `localStorage`,
поэтому со страницы карты можно сразу перейти к смете.

Тайлы OSM бесплатны, но их
[политика использования](https://operations.osmfoundation.org/policies/tiles/)
не рассчитана на коммерческий трафик. Для продакшена стоит подключить свой тайл-сервер
или Яндекс.Карты с ключом — меняется одна строка в `src/components/ComplexMap.tsx`.

## Режим менеджера

Вход по паролю на `/manager` ставит подписанную HMAC cookie на 12 часов. В этом режиме
в калькуляторе появляются:

* категорийная скидка (автоматически, по паре «категория ЖК + тип города»);
* поле персональной скидки — общей и отдельно по каждому ЖК;
* итоговая цена и сумма экономии клиента.

Скидочная сетка не попадает в браузер клиента: `public/dataset.json` собирается без неё,
на страницу она передаётся только при валидной сессии менеджера.

При сохранении расчёта менеджер может галочкой открыть клиенту цену со скидкой —
тогда по ссылке `/q/<id>` видна итоговая цена, иначе только прайс.

## Данные

Источник — Google-таблица «Основной медиаплан Умные экраны в ЖК».

```bash
npm run fetch:data   # скачать вкладки в data/source/*.csv
npm run build:data   # пересобрать dataset.json
```

`fetch:data` тянет вкладки «Основной эфир», «Генеральный баннер», «СВОД АП», «Стоп-лист»,
«Выбор адресов» и «ТТ». Скрытая вкладка «Стоп-лист застройщики» через экспорт недоступна —
она ведётся вручную в `data/source/developers.json`.

### Что делает конвертер

1. Разбирает CSV с учётом кавычек и **переносов строк внутри ячеек** — в исходнике около
   12 адресов содержат перенос и ломают наивный парсинг.
2. Схлопывает строки-размещения в дома по уникальному адресу. В таблице у дома с экранами
   и в холле, и в лифте — две строки с одинаковым числом жителей, поэтому простое
   суммирование задваивает охват.
3. Достраивает потерянные значения OTS (в исходнике `#REF!`) по среднему числу контактов
   на жителя × экран: 1 дом по видео и 11 домов по баннеру.
4. Исправляет опечатку «Венртикальный 4*3».

### Сверка с вкладкой «СВОД АП»

| Показатель | Сайт | СВОД | Комментарий |
|---|---|---|---|
| ЖК | 377 | 377 | сходится по каждому городу |
| Экраны | 2481 | 2481 | сходится по каждому городу |
| Дома | 658 | 653 | считаются уникальные адреса; в исходнике есть дубли с опечатками в адресе |
| Жители | 473 401 | 493 648 | в СВОДе жители задвоены у домов с двумя типами экранов |

### Расхождение по OTS — требует решения бизнеса

Во вкладке «Выбор адресов» OTS по ЖК считается как **среднее** по домам
(`AVERAGE(filter(...))`), а не как сумма. Например, ЖК Видинеевский: в таблице 11 882
контакта, фактическая сумма по пяти домам — 59 411.

Сайт считает **сумму** — это корректная величина для медиаплана: контакты на разных
экранах не пересекаются. Если отдел продаж должен показывать те же цифры, что в таблице,
переключение делается в `houseTotals()` в `src/lib/calc.ts`.

## Хранение расчётов

В серверной сборке расчёты пишутся JSON-файлами в `QUOTES_DIR`
(по умолчанию `.data/quotes/<id>.json`). Формат — `StoredQuote` из `src/lib/types.ts`.
Для перехода на базу достаточно переписать `saveQuote`/`loadQuote` в `src/lib/quotes.ts` —
остальной код их не знает.

Тело запроса на сохранение проходит через `sanitizeQuote`: обрезаются длины, ограничивается
число ЖК, а персональные скидки и флаг показа скидок принимаются только от менеджера.

## Структура

```
data/source/          выгрузки исходной таблицы + developers.json
scripts/              fetch-source.mjs, build-dataset.mjs, build-static.mjs
src/data/dataset.json полный датасет (сервер, со скидочной сеткой)
public/dataset.json   публичный датасет (браузер, без скидок)
src/lib/              типы, расчёты, доступ к данным, сессия, хранилище, ссылки-расчёты
src/components/       калькулятор, карта, смета и их части
src/app/              страницы и API-роуты (*.node.* — только серверная сборка)
```
